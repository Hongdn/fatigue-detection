## 二、系统架构总览

### 2.1 整体六阶段架构

工作状态分析位于完整 pipeline 的后段，复用前段的基础设施：

```
①数据采集 → ②前置处理 → ③特征提取 → ④模型推理 → ⑤融合决策 → ⑥输出
            （本模块跨③④⑤⑥，复用②的输出）
```

### 2.2 各层选型（已固化）

| 层 | 选型 | 作用 |
|----|------|------|
| 数据采集 | 电台语音流 + 值班排班日志 + ACDM 航班数据 + ASR转写文本 | 多源输入 |
| 前置处理 | ClearerVoice-Studio 降噪 + Silero VAD + **TSE目标提取（参考语音）** | 净化+分段+提取管制员语音 |
| 特征提取 | ①**openSMILE** eGeMAPS(88维,核心) + ②**文本认知指标**(~6维,核心) + ③embedding(可选) | 双路核心+可选扩展 |
| 模型推理 | TCN 维度回归（arousal/exertion）+ 个体基线对齐 | 状态估计 |
| 融合决策 | 规则引擎（语音↑+文本认知↑+值班↑+航班密度） | 状态判定 |
| 输出 | 状态轨迹图 + 分级告警 + 复核报告 | 业务交付 |

## 三、难点剖析

### 3.1 为什么工作状态分析是核心难点

| 对比项 | ASR 转写 | 指令一致性 | **工作状态分析** |
|--------|---------|-----------|----------------|
| 技术成熟度 | 成熟 | 半成熟 | **不成熟** |
| 现成数据集 | 有 | 有（指令规则） | **几乎没有** |
| 输出确定性 | 确定（文字） | 确定（对/错） | **不确定（主观连续态）** |
| 标注难度 | 低 | 中 | **极高** |
| 个体差异影响 | 小 | 小 | **大** |

### 3.2 六个核心难点

1. **状态定义模糊**——"兴奋/稳定/疲劳"是业务词，不对应任何公开 SER 数据集标签；"兴奋"在高峰期是正常应激，低密度时段才是异常
2. **疲劳 ≠ 低唤醒**（最易踩的坑）——疲劳晚期管制员为保持清醒会主动用力，唤醒度反而反弹，单看 arousal 会误判为"兴奋"
3. **状态与情境耦合**——脱离航班密度判状态无意义，高唤醒在高峰期是"正常稳定"
4. **没有标注金标准**——自评不准、带班主任评估稀疏、生理金标准干扰工作
5. **个体差异大**——老管制员语速本就慢，跨人比较会把老手全判疲劳
6. **机坪通话稀疏**——滑行慢、指令间隔长，特征样本不足，状态估计方差大

## 四、实现方案（核心）

### 4.1 破局思路：状态空间重定义

**不做三分类，改做"连续维度 + 趋势轨迹"**。

预测三个连续维度：
- **arousal（唤醒度）**：生理激活程度，高=警觉/兴奋，低=困倦
- **exertion（用力感）**：维持工作所需努力，高=费力
- **valence（效价）**：情绪正负向（紧张=负，从容=正）—可靠性低，弱化

三态是维度的业务解读，通过维度组合 + **时序趋势**映射：

| 状态 | 维度特征 | 判定要点 |
|------|---------|---------|
| 稳定 | arousal 在基线带内 + exertion 低 + 趋势平稳 | 默认态 |
| 兴奋 | arousal 显著高于基线（短期） | 需结合情境：高峰=正常应激，低密度=异常 |
| 疲劳 | arousal **持续下降趋势** + exertion **持续上升趋势** | **关键：是趋势，不是绝对值** |

**疲劳判定的核心**：是值班过程中的**迁移轨迹**，而非某个时间点的绝对值。
- 值班 2h：基线附近（稳定）
- 值班 4h：arousal 略降，exertion 略升（仍稳定，趋势显现）
- 值班 6h：arousal 持续降，exertion 持续升 → 进入疲劳区

**为什么引入 exertion**：疲劳晚期 arousal 会反弹（努力维持清醒），单看 arousal 会误判。exertion 捕捉"维持同等表现需要更多努力"，对应嗓音质量恶化（jitter/shimmer 上升、HNR 下降）。

### 4.2 完整实现 pipeline

    │
    ▼

    │                                                  │ 数据预处理层

[VAD] Silero 语音活动检测 ─→ 切出有效通话段            │ 复用 ASR 模块
    │                                                  │ 的输出）

[TSE目标提取] ClearerVoice 参考语音 ─→ 提取管制员纯净语音 ──┘
    │
    ├──────────────────┬──────────────────────────────┐

              │                                       │

[趋势计算] 5-10 分钟滑窗，计算 arousal/exertion 斜率   │
              │                                       │

### 4.3 特征提取（双路核心 + 可选扩展）

| 路线 | 工具 | 输出 | 服务维度 |
|------|------|------|---------|
| ①生理声学（核心） | openSMILE eGeMAPS | 88 维 | arousal + exertion 主力 |
| ②文本认知（核心） | ASR转写→口误率/复诵准确率/填充词/ASR置信度 | ~6 维 | 认知状态 |
| ③语音嵌入（可选） | Emotion2Vec+ embedding（不取标签） | 768 维 | 可选扩展，验证增益后决定 |

**关键特征与维度映射**：

| 维度 | 主特征 | 物理含义 |
|------|--------|---------|
| arousal | F0 均值/范围、能量、语速、谱重心 | 声学激活程度 |
| exertion | jitter、shimmer、HNR、能量动态范围收窄 | 嗓音质量恶化=用力 |
| valence | F0 轮廓、谱倾斜 | 情绪正负（可靠性低，弱化） |

**为什么用 eGeMAPS 而非自定义特征**：标准化、可复现、是疲劳研究事实标准，且 88 维足够轻量。

### 4.4 个体基线对齐（分班次）

```
对每个管制员 s、每个班次类型 b（白班/夜班/早班）：
  baseline[s,b] = 近30天 该班次 前2小时（已知清醒段）的特征均值/方差
当前样本 x 标准化：z = (x - baseline[s,b]) / std[s,b]
```

**为什么分班次**：管制员倒班制，夜班和白班的"正常"语音基线本就不同，混在一起会污染基线。

**冷启动**：新管制员前 2 周用群体基线兜底，输出标注"低置信度"，2 周后切个体基线。

### 4.5 维度估计模型

**模型架构**：TCN（时间卷积网络），输入特征序列，输出 0-1 连续维度值。

```
输入：标准化特征序列 [z_1, z_2, ..., z_t]（每段通话一个特征向量）
      ─────────────────────────────────────
TCN 层：膨胀因果卷积 × 4 层（感受野覆盖 10 分钟）
      │
全连接 → sigmoid
      │
输出：arousal_t ∈ [0,1], exertion_t ∈ [0,1]
```

**为什么用 TCN 而非 LSTM**：训练快、梯度稳、适合时序窗口聚合，且工程部署轻。

**训练数据**：
- DAIC-WOZ（抑郁/疲劳访谈，含 arousal 标注）—预训练
- RECOLA（连续 arousal/valence 标注）—预训练
- 自建机坪管制语料（弱标注）—微调

### 4.6 状态判定引擎（可解释规则）

**为什么用规则而非端到端分类**：
- 可解释（告警能给出理由："arousal 较基线下降 1.2σ，持续 40 分钟"）
- 可调参（不同机场/班次阈值不同）
- 不需要大量三态标注数据

```
输入：arousal_z, exertion_z（标准化值）,
      slope_a, slope_e（近30分钟趋势斜率）,
      情境标签（航班密度）

if |arousal_z| < 0.5 and exertion_z < 0.5 and |slope_a| < θ:
    state = 稳定

elif arousal_z > 0.8 and 情境 = 高峰/特情:
    state = 兴奋（正常应激，不告警）

elif arousal_z > 0.8 and 情境 = 低密度:
    state = 异常兴奋（黄色告警）

elif slope_a < -θ_a and slope_e > θ_e:        # 趋势判疲劳（核心）
    state = 疲劳（趋势，黄色告警）

elif arousal_z < -1.0 and exertion_z > 1.5:   # 晚期绝对值
    state = 疲劳（晚期，红色告警）

else:
    state = 稳定（默认）
```

### 4.7 多信号融合

| 信号 | 来源 | 在融合中的作用 |
|------|------|--------------|
| 语音维度（arousal/exertion） | 本模块 | 主信号 |
| 值班时长 | 执勤统计模块 | 趋势先验（>4h 疲劳概率上升） |
| 指令发布频率 | 指令识别模块 | 行为信号（频率下降=疲劳） |
| 航班密度 | ACDM 运行系统 | 情境修正（高峰期 arousal 偏高属正常） |

**融合方式**：一期规则加权（透明可调），二期可上 LightGBM 学习权重。

### 4.8 输出与告警

| 输出形态 | 内容 | 接收方 |
|---------|------|--------|
| 状态轨迹图 | 值班全程 arousal/exertion/状态曲线 | 带班长后台 |
| 实时告警 | 黄色（趋势疲劳）/红色（晚期疲劳/异常兴奋） | 带班长（不推管制员本人，避免干扰指挥） |
| 复核报告 | 班次结束后状态分析报告 | FRMS 留痕 |

**告警不对管制员本人**：避免干扰其指挥，只推带班长决策是否换班/提醒。

## 五、数据与标注策略

### 5.1 弱监督标注体系（不依赖精确标签）

| 标注源 | 标注内容 | 频率 | 用途 |
|--------|---------|------|------|
| 带班主任 | 三态主观评估 | 每班次 3-4 次 | 模型校准、告警验证 |
| PVT 警觉度测试 | 反应时（疲劳金标准） | 值班前后各 1 次 | 疲劳维度对齐 |
| 航班密度/特情事件 | 情境标签 | 自动 | 兴奋态情境修正 |
| 值班时长 | 时间标签 | 自动 | 趋势先验 |

### 5.2 数据采集（二期试点）

1. 选 1 个机坪管制班组，**离线分析历史录音**（不实时告警）
2. 同步采集带班主任评估 + PVT，建立弱标注语料库（目标 50-100 班次）
3. 验证"语音维度与 PVT/主观评估的相关性"（目标 r > 0.6）
4. 相关性达标后再上实时

### 5.3 学术数据预训练
- DAIC-WOZ：arousal/疲劳预训练
- RECOLA：连续 arousal/valence 回归预训练
- 自建机坪语料：微调

## 六、分阶段实施路线

| 阶段 | 目标 | 输出 | 验证标准 |
|------|------|------|---------|
| **阶段 1：疲劳先行** | 只做疲劳（趋势+晚期） | 疲劳分 0-1 + 告警 | 与 PVT 相关性 r > 0.6 |
| **阶段 2：兴奋/应激** | 增加情境修正的兴奋识别 | 兴奋态标记 | 高峰期误报率 < 20% |
| **阶段 3：完整三态** | 稳定/兴奋/疲劳连续输出 | 状态轨迹图 | 带班主任评估一致率 > 75% |

**为什么先做疲劳**：最明确、价值最高、有 PVT 金标准、带班主任最关心。兴奋/稳定争议大，放后面。

## 七、机坪管制场景适配

| 特性 | 影响 | 应对 |
|------|------|------|
| 通话频率低（滑行慢） | 特征样本稀疏 | 滑窗拉长到 10-15 分钟 |
| 指令模板化（推出/滑行/机位） | 个体风格差异小 | 利好：基线更稳定 |
| 中英混合（呼号英文+指令中文） | Emotion2Vec 多语言预训练 | 取embedding不取标签 |
| 机坪噪声（地面车辆、APU） | 信噪比差 | 前置 ClearerVoice-Studio 降噪 |
| 席位固定 | 可选配摄像头辅助 | 二期不建议上图像（隐私+成本） |

## 八、风险评估与验收标准

### 8.1 技术风险

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| 维度回归真实环境准确率不达标 | 高 | 核心功能失效 | 先离线验证相关性，达标再上实时 |
| 带班主任标注不一致 | 中 | 模型校准偏差 | 多人标注取多数，定期校准会 |
| 个体基线冷启动期误报 | 中 | 用户体验差 | 低置信度标注 + 前期只推报告不告警 |
| 兴奋/稳定边界争议 | 高 | 业务不接受 | 阶段 1 只做疲劳，兴奋放阶段 2 |

### 8.2 验收标准（可量化，不踩坑）

| 指标 | 阶段 1 目标 | 阶段 3 目标 |
|------|-----------|-----------|
| 疲劳告警灵敏度（漏报率控制） | ≥ 80% | ≥ 90% |
| 疲劳告警特异度（误报率控制） | ≥ 70% | ≥ 85% |
| 语音 arousal 与 PVT 相关性 | r ≥ 0.6 | r ≥ 0.7 |
| 带班主任评估一致率 | — | ≥ 75% |

**不要承诺"三态分类准确率 90%"**——疲劳没有金标准，所有准确率都是相对某个标签集的，跟客户讲灵敏度/特异度/相关性更实在。

### 8.3 合规前置

- 声纹属生物特征，需走《个人信息保护法》告知同意流程
- 二期启动前 3 个月启动合规
- 对齐 T/CATAGS106-2026 标准（本模块对应"警觉度+情绪状态"两维）

## 九、关键判断

> **工作状态分析能否落地，不取决于模型多先进，而取决于"能否拿到带状态标注的机坪管制语音数据"。** 模型是现成的（openSMILE+TCN），数据才是真正瓶颈。二期第一阶段必须先建语料库，再谈模型。

二期推进顺序：
1. **先做离线验证课题**（历史录音 + PVT 证明可行性）
2. **再建语料库**（50-100 班次弱标注）
3. **最后上实时**（灰度，先报告后告警）
