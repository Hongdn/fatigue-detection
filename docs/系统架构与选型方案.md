# 管制员疲劳监控系统 — 系统架构与选型方案

| 项 | 内容 |
|----|------|
| 文档版本 | v1.4 |
| 日期 | 2026-07-24 |
| 状态 | 方案论证（一期step1-6全链路编码完成） |
| 场景 | 航司 / 机场管制员（ATC）疲劳与状态监控 |
| 目标 | 通过电台语音 + 声纹 + 值班日志等多信号融合，辅助判断管制员疲劳状态，降低航空安全风险 |

---

## 1. 项目背景与核心判断

### 1.1 业务目标
管制员（Air Traffic Controller）在长时间值班、夜班、高负荷时段易出现疲劳，直接影响空管指挥质量与航空安全。本系统通过客观信号辅助识别疲劳趋势，为值班长排班调度、FRMS（疲劳风险管理系统）提供数据支撑。

### 1.2 核心判断（决定架构方向）
**纯语音情感识别（SER）不足以直接判断疲劳**，原因：

1. **疲劳是连续生理状态，不是离散情感**。SER 输出"愤怒/悲伤/中性"等标签，与"疲劳"并非同一维度。
2. **跨人差异极大**。同一特征（如话音低沉）对 A 是疲劳，对 B 可能是常态。必须做个体内对比。
3. **告警代价不对称**。漏报可能引发安全事故，误报扰乱排班、引发劳动关系纠纷。纯模型自动决策无人能担责。
4. **电台语音质量差**。VHF 8kHz 窄带、背景嗡声、串扰，直接喂深度模型准确率会暴跌。

**因此系统设计原则**：多信号融合 + 个体基线对齐 + 人工复核闭环，语音只作为其中一个信号源。

---

## 2. 场景特殊性分析

| 维度 | 特殊性 | 对设计的影响 |
|------|--------|--------------|
| 语音质量 | VHF 电台 8kHz 窄带、背景噪声、偶发串扰 | 必须前置降噪 + VAD |
| 语言 | 中英混合（数字/呼号英语，沟通偶尔中文） | 选用多语言 wav2vec2 XLSR |
| 通话模式 | 间歇性短句，非连续语音 | 时序窗口需滑窗聚合，不能按整段判别 |
| 多人值班 | 一个大厅多名管制员同时值守 | 必须声纹区分，做个体基线 |
| 监管 | 航空安全 + 劳动权益双重敏感 | 全程留痕，人工复核，不可全自动决策 |
| 班次 | 白班/夜班/倒班，"正常"基线本不同 | 基线需分班次维护 |
| 数据敏感 | 声纹属生物特征 | 需知情同意、本地化存储、定期删除 |

---

## 3. 系统架构总览

系统采用六阶段流水线，数据自上而下流动，人工复核结果回流形成闭环。

```
数据采集 → 前置处理 → 特征提取 → 模型推理 → 融合决策 → 输出
   ↑                                                    │
   └────────────── 人工复核结果回流（闭环） ─────────────┘
```

## 4. 各层选型详解

### 第 1 层 · 数据采集

| 信号源 | 说明 | 优先级 |
|--------|------|--------|
| 电台语音流 | 从空管自动化系统录音接口获取，主信号 | 必须 |
| 值班排班日志 | 班次、值班时长、距上次休息间隔；免费且关键 | 必须 |
| 可穿戴/行为 | 心率手环、鼠标键盘活动；一线接受度低 | 可选（二期） |

**选型理由**：
- 语音是唯一能反映"实时状态"的信号，但单独不够。
- 排班日志几乎零成本获取，且与疲劳强相关（连续值班第 4 小时 vs 第 1 小时，同样语音特征含义不同）。
- 可穿戴设备在管制大厅推行阻力大，建议二期再考虑。

### 第 2 层 · 前置处理（最易被低估的环节）

| 模块 | 选型 | 作用 |
|------|------|------|
| 降噪增强 | **ClearerVoice-Studio** MossFormerGAN_SE_16K | 提升信噪比，挽救窄带语音 |
| 目标说话人提取 | **ClearerVoice TSE**（基于参考语音，一步提取） | 用管制员参考语音从混合录音中提取，隔离飞行员 |
| 声纹身份校验 | ECAPA-TDNN（SpeechBrain） | 校验提取结果确认为目标管制员 |

**选型理由**：
- **降噪**：ClearerVoice-Studio MossFormerGAN_SE_16K，阿里 ModelScope 生态，与 FunASR 同栈；SSNR 14.03 dB，语音自然度 4.4/5，适配电台窄带场景。
- **TSE 目标提取是核心**（核实：录音为空管+飞行员混合）。ClearerVoice TSE 不依赖 VAD 切分或先识别身份——直接用管制员参考语音（3-5秒干净样本）作为 anchor，从混合录音中一步提取该人语音。链路简化为：降噪 → TSE(参考语音) → 管制员纯净语音 → openSMILE。参考语音需二期提前采集建库。
- **声纹身份校验**：ECAPA-TDNN 从"前置锁人"降级为"后置校验"——确认 TSE 提取出来的确实是指定管制员，不是串扰或误提取。

### 第 3 层 · 特征提取（双路核心 + 可选扩展）

| 路线 | 选型 | 维度 | 角色 |
|------|------|------|------|
| ①生理声学（核心） | **openSMILE eGeMAPSv02** | 88 维 | **核心路**，生理测量，可解释 |
| ②文本认知（核心） | ASR转写→口误率/复诵准确率/填充词/ASR置信度 | ~6 维 | **核心路**，认知状态 |
| ③语音嵌入（可选） | Emotion2Vec+ embedding（不取标签） | 768 维 | 可选扩展，验证增益后决定 |

**选型理由（已按实测修正）**：
- **①openSMILE 生理声学是核心**。疲劳是生理态，有声学物理基础：声带肌肉疲劳→jitter/shimmer 变化，呼吸变浅→能量下降。实测证明 openSMILE 能区分 Emotion2Vec+ 区分不了的状态。
- **②文本认知指标是核心（新增）**。ASR 转写文本反映认知状态：疲劳时口误增多、复诵错误、填充词增多、ASR置信度下降。**复诵准确率是金信号**（客观可判、复用课题5.2进阶一）。文本侧零采集成本（复用ASR输出），与声学特征互补（生理+认知双维度）。
- **③Emotion2Vec embedding 降为可选扩展**。实测 Emotion2Vec+ 分类输出失效；embedding 仍有表征价值但增益未验证。MVP 先纯 openSMILE+文本两路，embedding 作为 H5a 可选实验，验证增益后再决定是否纳入。
- **两路核心互补**：openSMILE 测生理（嗓音质量），文本测认知（语言流畅），疲劳时两路应一致恶化（arousal↓ + 口误率↑）。

### 第 4 层 · 模型推理（核心）

| 模块 | 选型 | 说明 |
|------|------|------|
| 个体基线对齐 | per-speaker z-score 标准化 | 取该管制员近 30 天"已知清醒时段"特征均值方差，当前样本标准化 |
| 疲劳打分模型 | LSTM 或 TCN（时序） | 5-10 分钟滑窗，输出 0-1 连续疲劳分 |

**选型理由**：
- **个体基线对齐是本产品的灵魂**。不跨人比较，只看个体相对自身常态偏离多少。新管制员冷启动期用群体基线兜底，标注"低置信度"。
- **LSTM/TCN 处理时序窗口**。单点特征无法判疲劳，必须看趋势。TCN 推理更快、可并行，LSTM 更成熟，二者均可，建议 TCN 起步。
- 训练数据：**ATC Fatigue Corpus**（Shen/NUAA, IEEE Dataport，700k 段真实空管疲劳标注）+ ExpressiveSpeech（DeEAR arousal 辅助验证）

### 第 5 层 · 融合决策

| 模块 | 选型 | 说明 |
|------|------|------|
| 多信号融合 | 规则加权起步 → 梯度提升树（后期） | 声学arousal/exertion + 文本认知指标 + 值班时长 + 距上次休息 |
| 告警引擎 | rule + ML 混合 | 分级告警，必须留人工复核出口 |

**告警分级示例**：
- 黄色：语音疲劳分 > 0.7 且连续值班 > 4h
- 橙色：连续 3 个窗口（15 分钟）疲劳分 > 0.8
- 红色：多信号融合分 > 阈值且值班长主观确认

**选型理由**：
- 规则起步可解释、可审计，符合航空监管要求。ML 融合后期再上，且必须可解释（如 SHAP）。
- 告警必须有出口给人，不能全自动触发调度动作。

### 第 6 层 · 输出与闭环

| 输出 | 接收方 | 说明 |
|------|--------|------|
| 实时告警 | 带班 / 值班长 | 不直接推管制员本人，避免干扰指挥 |
| 趋势报告 | FRMS 系统 | 事后分析、排班优化、监管留痕 |
| 复核反馈 | 回流模型训练 | 人工确认/驳回结果，更新个体基线 |

## 6. 合规与标准

### 6.1 适用的标准与法规

| 标准/法规 | 范围 | 要点 |
|-----------|------|------|
| ICAO Doc 9966 | 国际 | 疲劳风险管理（FRMS）国际框架，系统设计需对齐 |
| CAAC AC-121-FS | 国内 | 民航疲劳风险管理咨询通告 |
| 《个人信息保护法》 | 国内 | 声纹属生物特征，需单独同意、明示目的、可撤回 |
| GDPR（涉外航司） | 欧盟 | 生物特征属特殊类数据，默认禁止处理 |

### 6.2 必须执行的合规动作

1. **员工知情同意书**：明确告知采集内容、用途、存储期限、撤回方式
2. **数据本地化存储**：不出航司内网，不上公有云
3. **定期删除机制**：原始语音按周期删除，只保留特征向量与得分
4. **人工复核环节**：告警必须经人工确认，不可全自动决策影响劳动者权益
5. **审计日志**：所有告警、复核、模型更新全程留痕

## 7. 落地路径

### 阶段一 · MVP（已完成）
- 用 ExpressiveSpeech（28k 条，DeEAR 标注）跑通全链路
- step1(降噪+VAD) → step2(openSMILE 88维) → step4(XGBoost+SHAP双任务回归) → step5(规则引擎+个体基线+SHAP溯源) → step6(Gradio Demo)
- CCC_arousal=0.873, CCC_exertion=0.617 — 验证通过
- step3 特征级 z-score 基线保留代码但不接入（XGBoost 树模型对尺度不敏感，个体归一化由 step5 SpeakerBaseline 在输出级完成）
- 参配：300 trees, depth=6, CPU 2s 训练, 模型文件 < 2MB

### 阶段二 · 试点（3-6 个月）
- 选 1 个航司、1 个管制大厅，**离线分析历史录音**（不实时告警）
- 采集该单位管制员数据，建个体基线
- 与值班长主观评估做相关性验证，目标 AUC > 0.8
- 同步走合规流程（告知同意、数据协议）

### 阶段三 · 生产（6-12 个月）
- 实时接入电台流，灰度上线告警
- 先只推"趋势报告"，不推实时告警；运行 1-2 个月无误报后再开实时
- 建立 FRMS 数据闭环，人工复核结果回流训练

| 3 | 新管制员基线冷启动 | 前 2 周用群体基线兜底，标注"低置信度" |
| 4 | 倒班制干扰基线 | 基线分班次维护（白班/夜班/倒班各一套） |

| 9 | **录音质量干扰特征**（实测教训） | jitter/shimmer 对噪声极敏感；必须 ClearerVoice-Studio 降噪前置 + 录音质量门控（质量差的段降权/丢弃）+ 多特征交叉验证，不可单点单特征判疲劳 |

## 9. 关键指标定义（附录）

| 指标 | 定义 | 目标 |
|------|------|------|
| 疲劳分 | 模型输出的 0-1 连续值，越接近 1 越疲劳 | — |
| AUC | 与人工标注的 ROC-AUC | 试点 > 0.8 |
| 误报率 (FPR) | 非疲劳被报为疲劳的比例 | < 10% |
| 漏报率 (FNR) | 疲劳未被识别的比例 | < 20% |
| 告警响应时延 | 从特征产生到告警推送 | < 30 秒 |
| 个体基线窗口 | 用于计算基线的历史数据时长 | 30 天滚动 |
| 时序滑窗 | 单次打分聚合的语音时长 | 5-10 分钟 |
